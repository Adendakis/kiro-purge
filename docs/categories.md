# Storage Categories

## Category Mapping

Each file in the Kiro storage directory is classified into exactly one category based on its path. Classification uses directory-based matching first, then file extension matching, with uncategorized as the fallback.

### Priority Order

1. **Index** (most specific path) — `User/globalStorage/kiro.kiroagent/index/`
2. **Chats** — `User/globalStorage/kiro.kiroagent/**/*.chat`
3. **Directory-based categories** — logs, cache, history, crash_reports
4. **Temp extensions** — `*.tmp`, `*.temp` (only for files not already categorized)
5. **Uncategorized** — everything else

### Detailed Mapping

| Category | Paths (relative to Kiro storage) | Description |
|----------|----------------------------------|-------------|
| `logs` | `logs/` | Application log files generated by Kiro |
| `cache` | `Cache/`, `CachedData/`, `GPUCache/` | Chromium browser engine cache data |
| `chats` | `User/globalStorage/kiro.kiroagent/**/*.chat` | Conversation history with Kiro AI |
| `index` | `User/globalStorage/kiro.kiroagent/index/` | Code intelligence vector index (PROTECTED) |
| `temp` | `**/*.tmp`, `**/*.temp` | Temporary files anywhere in storage |
| `history` | `User/History/` | Local file edit history (undo snapshots) |
| `crash_reports` | `Crashpad/` | Crash dump files for Kiro debugging |
| uncategorized | Everything else | Extensions, workbench state, databases, etc. |

## Safety Classification

### ✅ Safe to Delete (no project impact)

- **cache** — Browser engine cache. Rebuilt automatically when Kiro starts. No user data.
- **logs** — Diagnostic logs about Kiro's internal operations. Not related to your code.
- **crash_reports** — Crash dumps for Kiro developers. Only useful for bug reports.
- **temp** — Transient files that should have been cleaned up already.

### ⚠️ Delete with Caution

- **history** — Local file edit history. Provides "time travel" for file changes outside of git. If you rely on git for version control, this is low-risk. But if you have uncommitted experimental changes you might want to recover, keep it.

### ❌ Contains Project Context

- **chats** — Your full conversation history with Kiro. Contains decisions, explanations, code discussions, and context that Kiro uses to understand your projects. Deleting old chats means losing that context permanently.

### 🔒 Protected (never deleted)

- **index** — Code intelligence index. Even if you select the "index" category, files inside the `index/` directory are protected and will be skipped. The index is rebuilt by Kiro but takes time and resources.

## Retention Periods

Categories with time-based retention only delete files older than the threshold:

| Category | Default Retention | Behavior |
|----------|-------------------|----------|
| logs | 7 days | Only logs older than 7 days are eligible |
| crash_reports | 30 days | Only crash dumps older than 30 days |
| history | 30 days | Only history entries older than 30 days |
| chats | 30 days | Only chats older than 30 days |
| cache | 0 (always) | All cache files are always eligible |
| temp | 0 (always) | All temp files are always eligible |
| index | 0 (always) | Would be eligible, but protected directory prevents deletion |

The `--keep-recent N` flag overrides the default retention for logs, crash_reports, history, and chats. Cache and temp are always fully eligible regardless of this flag.

## Size Expectations

Typical Kiro storage sizes after extended use:

| Category | Typical Range | Growth Rate |
|----------|---------------|-------------|
| chats | 1–20 GB | Grows with usage (each conversation ~50KB–5MB) |
| index | 1–10 GB | Proportional to codebase size |
| cache | 100 MB–1 GB | Bounded by Chromium cache limits |
| logs | 100 MB–2 GB | Grows daily, old logs accumulate |
| history | 100 MB–1 GB | Proportional to file edit frequency |
| crash_reports | 0–100 MB | Only grows when Kiro crashes |
| uncategorized | 5–30 GB | Extensions, workbench state, databases |
